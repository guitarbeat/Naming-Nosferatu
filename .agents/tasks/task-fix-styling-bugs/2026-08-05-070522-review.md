# Styling bug fixes: z-index stacking, TW4 token registration, dead config removal

This change resolves three classes of visual bugs in a React 19 + Tailwind CSS 4 app. First, modal and lightbox overlays rendered *beneath* the floating navbar (z-index 1000) because they used `z-40`/`z-50` (literal values 40/50). Second, several utility classes referenced in components — `bg-stardust/20`, `animate-blob`, `animation-delay-2000` — produced no CSS output because their tokens and keyframes were never registered in the TW4 `@theme` inline block. Third, the `TournamentComplete` hero used `w-screen` which causes horizontal overflow when a scrollbar is visible. The fix also deletes a dead `tailwind.config.js` that TW4 never loaded (no `@config` directive), eliminating a source of contributor confusion.

**Watch for:** The z-index escalation to 9998/9999 is internally consistent but creates a wide gap between the token system's `--z-modal: 300` and the actual values in use — any future component using the token will sit below the navbar (confirmed). The `--duration-fast: 100ms` value sits between `--duration-micro: 80ms` and `--duration-quick: 120ms`, which is tight spacing (possible concern — may not be intentional differentiation vs. a pick-one-and-alias situation).

**Verdict**: APPROVED

## High-level view

The z-index fix lifts Modal and Lightbox to `z-[9998]`/`z-[9999]`, well above the navbar's `--z-sticky: 1000`. This works, but the existing z-index token scale (`--z-modal: 300`, `--z-modal-backdrop: 1050`) is now inconsistent with these hardcoded values — anyone reaching for the tokens will get the wrong result.

TW4 token registration adds `--color-stardust` to the `@theme inline` block and a new `--duration-fast` variable to the `:root` motion tokens, enabling utility classes that previously emitted no CSS. The blob keyframes and utility classes complete the ambient animation system already referenced in components.

Deleting `config/tailwind.config.js` is pure cleanup. TW4 with `@tailwindcss/vite` doesn't load a JS config unless a `@config` directive is present in CSS — the file was dead weight whose color definitions could mislead contributors.

The `TournamentComplete` overflow fix replaces `w-screen` (which includes scrollbar width, causing horizontal overflow) with `w-full`, and drops the `marginInline` hack that tried to compensate. The component already sits in a full-width flex container, so `w-full` is correct.

## Z-index escalation and token inconsistency

The fix uses arbitrary values `z-[9998]` for the overlay and `z-[9999]` for the dialog panel. The lightbox gets `z-[9998]`. These sit just below `--z-max: 10000` (reserved for the boot screen), which is the correct ceiling.

The gap this creates is real: `tokens.css` defines `--z-modal: 300` and `--z-modal-backdrop: 1050`. Neither token is actually referenced by Modal.tsx — they appear to be vestigial from a TW3 era. Any contributor consulting tokens.css for "what z-index should my modal use?" will find values that place content *below* the navbar. The tokens should be updated to 9998/9999, or the components should reference `var(--z-modal)` with the tokens updated.

```css
/* tokens.css currently says: */
--z-modal-backdrop: 1050;
--z-modal: 300;

/* But Modal.tsx actually uses: */
z-[9998]  /* overlay */
z-[9999]  /* panel */
```

## TW4 token registration: duration-fast crowding

`--duration-fast: 100ms` plugs a gap in the motion token scale that left `--analysis-duration-fast: var(--duration-fast)` resolving to nothing. The value 100ms is functional, though the 80/100/120 spacing across micro/fast/quick is unusually tight — most design systems would collapse two of these into one or alias them.

## Blob animation easing

`animate-blob` uses `animation: blob 7s infinite` with no explicit timing function, defaulting to `ease`. Blob animations typically look more organic with `ease-in-out` or a custom cubic-bezier. This is a polish concern, not a bug, but worth a design check.
